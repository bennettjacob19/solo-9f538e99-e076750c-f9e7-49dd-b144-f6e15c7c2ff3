# 遥测 UDP 代理（接收器 A/B 切换 + 会话配额控制）

遥测终端经 UDP 代理把短报文发给接收器。值班员在两个网页上分别完成：

- **代理控制台**：切换接收器 A/B、发送试传报文（可选源 IP 与源端口）、查看会话与日志；
- **配额控制台**（独立服务）：设置全局活动会话上限（2～16）与单来源 IP 上限（1～8），
  查看“保存版”与“代理已确认版”的生效状态。

异常终端不断更换 UDP 源端口占满上游端口的问题，由代理侧的会话配额从首包起拦截。

## 组成

| 组件 | 说明 |
|---|---|
| `proxy/` | asyncio UDP 代理 + Flask 控制台 + SQLite 持久化（目标接收器、报文日志） |
| `control/` | **独立配额控制服务**：Flask 配额网页 + SQLite 版本持久化 + 推送/重试 |
| `receiver/` | 本地接收器，原样回显报文，可延迟回包 |
| `docker-compose.yml` | 一键启动接收器 A/B + 代理 + 配额控制服务 |
| `scripts/verify_local.py` | 无 Docker 环境下的端到端行为验证（83 项检查） |

## 启动

```bash
docker compose up --build
```

- 代理控制台：http://localhost:8080
- 配额控制台：http://localhost:8081
- 遥测终端发送地址：`UDP <宿主机>:9000`

## 配额规则（代理按“已应用版”执行）

- **首包即计数**：会话从第一个报文起就占名额，建连中（opening）也计入，
  因此异常终端无法靠“只发首包、不完成建连”囤积上游端口。
- **单来源 IP 满额即拒**：同一来源 IP 的会话数达到单 IP 上限时，新首包直接丢弃
  （不分配上游端口），日志记录拒绝原因。
- **全局满额的腾退**：全局会话数达到上限时，若存在“占有多于一席”的来源，
  关闭其中**最久未活动**的会话为新来源腾出名额；若每个来源都只占一席，则拒绝新会话。
- **被腾退/过期会话的迟到回包不投递**：会话关闭即关闭其独立上游 socket，
  端口进入冷却期不再分配，迟到回包由内核丢弃，不可能落到同 `IP:端口` 重建的会话。
- **收紧上限不踢旧会话**：新上限只影响接纳，已有会话照常透传；
  用量回落到新上限以内之前不接纳新会话。
- **名额归还**：空闲过期（`SESSION_IDLE_TIMEOUT`）或建连失败都会释放名额。

## 配额版本的保存、确认与生效

- 配额控制服务每次“保存”生成一个**只增不改的新版本**（事务落库）；
  保存失败不会改动当前保存版或待应用版。
- 控制服务后台把最新**保存版**推送到代理内部接口 `POST /internal/quota`；
  代理确认应用后，控制服务记录为**已确认版（已应用版）**，网页才显示“已生效”。
- 联系代理失败时，保存版保留为**待应用版**，推送线程按间隔自动重试；
  控制服务重启后从 SQLite 读出未应用版本，继续推送。
- 代理始终只按已应用版配额接纳；控制服务不可用不影响已有会话照常透传。
- **代理重启**：必须先从控制服务 `GET /api/quota/saved` 取得保存版，
  然后才绑定 UDP 监听、接纳新会话（取不到就持续重试，期间不监听数据面端口）。
- 代理内部还提供 `GET /internal/quota` 查询当前已应用版。

## 代理的原有行为（保持不变）

- **会话**：按客户端 `IP:端口` 建立，空闲 5 秒（`SESSION_IDLE_TIMEOUT`）无收发即过期。
- **建会话时固定接收器**：会话期间的一切报文都发往建会话那一刻的目标接收器；
  网页切换 A/B 只影响之后新建的会话，旧会话继续走原接收器直到过期。
- **原样透传**：报文与回包内容不做任何修改。
- **回包不错投**：每个会话使用一条独立的、已 connect 到其接收器的上游 UDP
  套接字（独立本地端口），只有该会话对应接收器的回包会被送回该客户端。
- **切换可靠性**：切换先写 SQLite 再生效，保存失败保留原目标并在网页报错。
- **重启**：目标接收器保存在 SQLite（`proxy-data` 卷）重启后保留；
  会话全在内存，重启即清空。

## 网页功能

### 配额控制台（:8081）

- 设置全局上限（2～16）、单来源 IP 上限（1～8），保存为新版本；
- 卡片展示保存版、代理已确认版、生效状态（已生效/待应用）与最近联系结果；
- 版本历史表显示每个版本是“代理已确认 / 待应用 / 已被取代”。

### 代理控制台（:8080）

- 切换目标接收器 A/B；
- 配额卡片：已应用版本号、全局/单 IP 上限、当前总会话用量、每来源 IP 用量、
  启动取版状态；
- **发送试传报文**：可选**源 IP（127.0.0.1～127.0.0.3）**、固定源端口、
  回包延迟与等待超时；结果显示实际源地址、去向接收器、回包与 RTT；
  被配额拒绝时显示拒绝原因；
- 活动会话 / 报文日志（含配额拒绝、腾退事件）实时刷新。

## 接收器延迟回包

- 环境变量 `REPLY_DELAY`：该接收器所有回包的默认延迟秒数。
- 报文级覆盖：报文以 `DELAY:<秒>:` 开头时按该值延迟（回包仍是完整原始报文）。

## 配置（环境变量）

### 代理 `proxy/`

| 变量 | 默认 | 说明 |
|---|---|---|
| `UDP_LISTEN_PORT` | `9000` | 代理对终端的 UDP 监听端口 |
| `HTTP_PORT` | `8080` | 代理控制台端口 |
| `SESSION_IDLE_TIMEOUT` | `5` | 会话空闲超时（秒） |
| `RECEIVER_A_HOST/PORT`、`RECEIVER_B_HOST/PORT` | 见 compose | 接收器地址 |
| `DB_PATH` | `/data/proxy.db` | SQLite 路径（目标持久化、日志） |
| `UPSTREAM_PORT_MIN/MAX` | `20000/29999` | 上游本地端口池 |
| `UPSTREAM_PORT_COOLDOWN` | `30` | 上游端口关闭后的冷却秒数 |
| `QUOTA_CONTROL_URL` | （compose 内为 `http://control:8081`） | 配额控制服务地址；留空则不启用对接，用内置默认配额 |
| `QUOTA_FETCH_INTERVAL` | `0.2` | 启动时取保存版的重试间隔（秒） |
| `QUOTA_HTTP_TIMEOUT` | `3` | 调用控制服务的超时（秒） |

### 配额控制服务 `control/`

| 变量 | 默认 | 说明 |
|---|---|---|
| `HTTP_PORT` | `8081` | 配额控制台端口 |
| `DB_PATH` | `/data/control.db` | SQLite 路径（保存版/已确认版持久化） |
| `PROXY_CONTROL_URL` | `http://proxy:8080` | 代理内部接口基址 |
| `APPLY_INTERVAL` | `1` | 待应用版本的重试推送间隔（秒） |
| `HTTP_TIMEOUT` | `3` | 调用代理的超时（秒） |

## 本地验证（无需 Docker）

```bash
pip install flask
python3 scripts/verify_local.py
```

逐项验证（共 83 项）：原样透传（含二进制）、切换后旧会话走原接收器、
过期后新会话走新接收器、迟到回包不投递、网页试传（源 IP/源端口/配额拒绝）、
重启保留目标并清空会话、切换保存失败保留原目标，以及配额专项：

- 首包（含 opening）即计数、单来源满额拒绝且不耗上游端口；
- 全局满额腾退占多席来源中最久未活动的会话、各占一席时拒绝、腾退后迟到回包不投递；
- 收紧上限不踢旧会话、用量回落前不接纳、空闲过期/建连失败归还名额；
- 保存版与已确认版的展示、越界与保存失败保护、代理联系失败保留待应用版；
- 控制服务重启后续推待处理版本；代理重启先取保存版再监听 UDP；
- 控制服务不可用时代理不提前接纳，恢复后自动取得配额启动。
